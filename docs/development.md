# 开发与维护

## 源码边界

| 路径 | 职责 |
| --- | --- |
| `tools/dsize.zsh` | 统计函数、帮助、参数校验和独立补全 |
| `tools/init.zsh` | 使用自身位置加载 mst 并显式注册工具；管理区之外允许用户自定义 |
| `lib/mst.zsh` | 任意目录可用的 Zsh 管理函数，根据定义文件定位已安装启动器 |
| `scripts/tools.list` | 安装包的可用工具文件名，不包含保留的 `init.zsh` 和 `mst.zsh` |
| `scripts/installer.sh.in` | 引导与常驻管理器共用的 POSIX sh 实现，负责参数、联网、清单、备份及会话 |
| `scripts/bootstrap.sh.in` | 展开管理器载荷，将引导执行与暂存目录交给共享实现 |
| `scripts/build-installer.sh` | 将工具、管理入口及许可打包为管理器，再嵌入单文件引导脚本 |
| `install.sh` | 可独立分发的生成产物，不手动编辑内嵌实现 |
| `tests/` | 不依赖额外测试框架的 macOS 隔离行为检查 |
| `docs/tools/<工具名>/` | 每个工具独立的英文及中文使用文档 |
| `LICENSE` | MIT 许可；生成安装器也包含完整声明 |

工具运行、查询和卸载没有网络依赖；安装、工具更新及管理器升级使用系统 curl。无需包管理器或额外运行时。不新增其他工具或通用插件协议，直到出现明确需求。

## 修改与生成

修改 `tools/`、`lib/`、安装模板或清单后执行：

```sh
sh scripts/build-installer.sh
sh scripts/check.sh
```

只检查产物是否同步：

```sh
sh scripts/build-installer.sh --check
```

生成过程只使用基础 Shell 工具，无时间或机器信息，因此结果可重复。清单中每行一个 `.zsh` 文件名，工具标识以小写字母或数字开头，仅允许小写字母、数字和连字符。不放注释、重复项、路径或管理器保留文件名。生成器检查两层 heredoc 分隔符冲突，并对管理器与引导脚本执行语法检查。修改许可时也需重新生成；提交时同时包含源码及生成的 `install.sh`。

## 新增工具

1. 在 `tools/` 新建独立文件，例如 `git-tools.zsh`，包含自己的函数、帮助和补全，内部函数用项目及工具前缀避免重名。
2. 在 `init.zsh` 的管理区域显式 source，并检查文件存在。不要 glob 执行目录中的所有 `.zsh`。
3. 将文件名加入 `scripts/tools.list`，重新生成 `install.sh`。
4. 增加实际行为检查和工具独立的 `README.md`、`README-cn.md`；根目录双语 README 的工具表格只添加名称、简介和链接。
5. 在真实 macOS 上运行完整门禁。用户先安装 mst，通过 `mst upgrade` 获取新工具目录，再按需执行 `mst install <工具名>`；共用集中入口，不增加额外 `.zshrc` 引用。`mst update` 只处理已安装工具。

仓库中的 `tools/init.zsh` 供直接加载源码使用。安装器按目标机器的已安装清单渲染管理区，不会将整个源码入口中的工具全部启用。管理测试临时生成双工具包，避免仓库中只有一个工具时掩盖全量安装错误。

工具只做函数定义和必要补全注册。不要在 source 或补全中扫描磁盘、联网、输出启动信息、运行 `compinit` 或更改调用者的选项及工作目录。

## 管理器与工具的边界

不带参数的 `install.sh` 只安装管理器，不写具体工具或工具清单；显式 `install` 无工具名时才选择全部工具。安装器展开的 `manager-core.sh` 是函数库，不自动调用主函数，供引导脚本及已安装启动器共用。

安装后的 `.mac-shell-tools/mst.sh` 固定解析后的工具目录和主配置路径，`mst.zsh` 根据自身位置找到它。首次引导和下载委托均由同一共享实现执行，避免维护两套安装逻辑。`.zshrc` → `init.zsh` → `mst.zsh` 仅定义函数，启动时不联网。

`mst install` 获取最新包并保存管理器及指定工具；`mst update` 获取最新工具内容，但不替换管理器；`mst upgrade` 仅更新管理器、目录及入口，不改具体工具文件或安装选择。`list` 和 `uninstall` 只使用本地内容。在线命令先检查下载与语法、清理下载暂存，再 exec 新引导脚本；固定路径和会话选项随委托传递。不要让在线委托递归下载，也不要让新 Zsh 持有旧锁或暂存目录。

## 安装配置契约

主配置管理标记：

```text
# >>> mac-shell-tools >>>
# <<< mac-shell-tools <<<
```

集中入口工具管理标记：

```text
# >>> mac-shell-tools managed tools >>>
# <<< mac-shell-tools managed tools <<<
```

标记要求每对唯一且顺序完整。无管理标记的已有入口不能自动覆盖。入口自定义区域保持；主配置只重置项目块并放在末尾，不搜索删除其他 source 行或函数。

安装顺序为全部暂存与语法检查 → 所有目标预检 → 管理器（需要时）→ 指定工具 → 安装清单 → 入口 → 主配置。仅安装或升级管理器时跳过工具与清单写入。卸载先移除入口中的注册，再备份和删除指定工具，最后更新或删除清单。卸载全部工具保留 mst、集中入口及主配置引用，始终保留共享目录和个人内容。

写入或删除前备份，名称用时间加随机后缀；逐文件同目录暂存后重命名，保留已有文件权限。操作不是跨文件事务；中途失败按报错修复后重试或配套恢复备份。文件及最终工具/管理器目录的符号链接直接拒绝，父目录链接通过物理目录定位保留。并发锁只保护同一工具目录。

安装清单 `.mac-shell-tools-installed` 是经过严格文件名和重复检查的纯文本，不执行其内容。自动会话仅在有文件变更且 stdin/stdout 都为终端时启动，支持参数与 `RUNZSH` 关闭；`exec zsh -l` 前必须清理暂存和本进程的锁。完整用户契约见[安装说明](installation-cn.md)。

## 验证门禁

`sh scripts/check.sh` 在 macOS 上执行：

- POSIX sh 与 Zsh 语法检查，生成产物一致性。
- `tests/dsize.zsh`：实际 BSD 命令结果比对、参数和路径矩阵、部分扫描、各管道阶段失败、中断、加载和调用隔离。
- `tests/install.sh`：临时 HOME 中的首次及重复安装、升级与恢复、同时间戳备份、用户区域、引号及中文路径、类型及权限错误、符号链接和单文件/stdin 分发。
- `tests/management.sh`：临时双工具包中的增量安装、选择更新、单项及全量卸载、清单校验、缺失文件修复、个人入口保留和管理参数转发。
- `tests/mst.sh`：默认只安装管理器、任意目录入口、离线管理、本地模拟在线发布包、升级与工具更新分离、新工具发现、无效下载保留原文件，以及固定自定义路径。
- `tests/completion.zsh`：系统 Zsh、`compinit` 和 `zpty` 中真实按 Tab，验证编辑缓冲区、选项数值、等号、参数顺序、`--`、无第二目录和无扫描。
- `tests/sessions.zsh`：隔离真实伪终端中首次引导、在线安装/更新/升级和卸载后的登录 Zsh，验证函数加载、固定 ZDOTDIR、锁及三类暂存清理、参数禁用、管道与输出重定向，以及推荐的 `sh -c` 入口。

配置验证绝不指向真实 HOME，在线测试使用本地 curl 替身，不安装远端代码。权限验证在可绕过权限的身份下会明确输出 SKIP；受控 du 失败检查仍执行。CI 使用 macOS runner；不以 Linux 通过替代 BSD 平台证据。

## 人工终端检查

自动化覆盖语义，以下项目用于检查个人终端和 Oh My Zsh 插件的显示及兼容性：

1. 在隔离配置下安装后确认进入新 Zsh，`mst list` 可用且未安装工具；选择安装 dsize 后检查 `dsize --help`。关闭自动启动时按打印命令加载。
2. 输入 `dsize -` 后按 Tab，查看短、长及帮助选项；分别对 `-d `、`-n `、`--depth=` 和 `--lines=` 查看候选及提示文字。
3. 对带空格或中文的目录按 Tab；交换选项和目录位置，并尝试 `dsize -- ./-`。
4. 确认个人补全主题和菜单显示正常，重复 source 能刷新定义；有同名函数时检查自定义加载顺序。

不用为了人工检查而修改项目之外的配置；可在独立 Zsh 中先初始化补全，再 source `tools/init.zsh`。
